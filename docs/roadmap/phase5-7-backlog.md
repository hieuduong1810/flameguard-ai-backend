# Backend backlog: Phases 5–7

**Status:** Proposed planning backlog, 2026-11-12. No endpoint, provider, scientific result or external integration in this file is implemented or approved for execution. Use Specify → Clarify → Plan → Tasks → Analyze → Implement → Test → Converge for each bounded slice.

## Baseline and boundaries

Phase 4 already exposes dashboard summary, investigation catalog/detail, runs, conditions, measurements, sources, claims and `POST /api/v1/compare` for 2–3 studies. Its comparison returns original observations with `comparability=not_established` and no derived deltas. Do not recreate those routes or claim they establish scientific comparability. T078 still awaits Frontend acceptance. Existing `scenario`, `scenario_match`, `match_dimension`, chat and prediction tables are structures, not working algorithms or validated outputs.

The Data Team owns NASA acquisition/ETL/import, curation, source QA and the dataset ranking algorithm. The AI Team owns retrieval/RAG, scientific prediction, model evaluation and uncertainty methodology. Backend owns public HTTP/Pydantic contracts, provider adapters, orchestration, validation, persistence, provenance/error checks and automated tests. Frontend owns client adaptation and user interface. All new endpoints below are **proposals** under `/api/v1`, subject to consumer contract review and the [Data integration gates](data-integration-pending.md).

Readiness labels: **Ready to specify** means the backend can write a bounded contract with synthetic fixtures, not that scientific behavior is ready. **External gate** means implementation may proceed only for independent contract/mock portions until the named owner supplies accepted evidence. **Decision needed** means a material schema, privacy or API choice must be resolved before that part of implementation.

Scientific rules across all phases: preserve UUID/PSI ID/slug/run key separately; exact original values, units, nulls, quality flags, source locators and review status; distinguish relevance from risk probability; never treat synthetic/mock output as NASA evidence. Numeric gravity/airflow must have explicit unit mapping to current string persistence fields. A combined evidence match requires compatible values in the **same run**. Public PSI data is engineering rehearsal; evaluate the official hackathon dataset on arrival. The 21-table ERD is the current baseline and may evolve only through the [reviewed policy](../decisions/ADR-0003-schema-evolution-and-hackathon-prototype.md).

## Shared implementation gates and verification

Each slice needs a spec/plan/tasks and approval before code. Define canonical Pydantic DTOs and `Router → Service → Repository → Database` boundaries; use Poetry, async SQLAlchemy, bounded queries, sanitized errors and explicit transaction ownership. Run HTTPX/OpenAPI contract tests, focused unit tests, and PostgreSQL integration tests on an isolated approved target. Record mock, real Data, real AI and Frontend checks separately. Any schema change requires an additive Alembic revision after approved impact analysis; never edit `0001`–`0003` or reset shared data.
